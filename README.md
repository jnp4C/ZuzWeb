# Dynamic Architecture Portfolio

Static architecture portfolio with a project index, bilingual project pages,
image carousels, and optional animated presentations.

## Working branch and publishing

Use `deployment-final` for all further website edits. It tracks
`origin/deployment-final`, the branch used by GitHub Pages. Fetch and pull before
starting work on another computer. Commit and preview changes locally; pushing
this branch triggers `.github/workflows/pages.yml`, which publishes only the
filtered site generated by `scripts/build-pages.mjs`. Local reference folders
are ignored and are never included in the published bundle.

## Final design touches on another computer

Clone the repository and check out the finishing branch:

```bash
git clone --branch deployment-final https://github.com/jnp4C/ZuzWeb.git
cd ZuzWeb
```

For an existing clone with a clean working tree:

```bash
git fetch origin
git switch deployment-final
git pull --ff-only origin deployment-final
```

Open this folder in your coding agent and tell it:
“Read AGENTS.md, help me set up the local preview, and start the server.
I will describe the final design changes.”

`AGENTS.md` includes the setup workflow and existing design rules. Local source
references in `Redesign/` are ignored and are not included in the clone; the
tracked website can be previewed without them.

## Local development

No build step or npm dependencies are required. Install Python if needed, then
run from the repository root (keep the terminal open):

```bash
# macOS / Linux
python3 -m http.server 8080 --bind 127.0.0.1
```

```powershell
# Windows
py -m http.server 8080 --bind 127.0.0.1
```

Open [http://127.0.0.1:8080](http://127.0.0.1:8080).
Use HTTP because project data and PDF features do not reliably work with
`file://`. Stop the server with Ctrl+C. If the port is busy, use 8081 instead.

## Static presentation branch

`deployment-final` combines the latest design refinements with `deployment-final` and uses complete static PDF page images for every published full
presentation. Pages load lazily, retain their original proportions, and scroll
in the main document. The PDF download remains available.

The dynamic implementation is preserved on `design-final-touch` for future
animation work. Legacy scene files are retained but are not loaded by full
presentations on this branch.

## Customize content

- Edit project text and metadata in `data/projects.json`.
- Set `visibility` to `published` only for projects intended for public display.
- Published projects use `projectPage.layout: "concise"`; curated media overrides
  live in `project-media.js`.
- Full presentations use `projectPage.fullPresentation.pages`, ordered static
  page images with original dimensions and responsive sources. Keep complete
  page sequences and the matching `download.href` PDF.
- Legacy `scenes` and PDF scene mappings are retained for dynamic development
  on `design-final-touch`; they do not control current static presentations.

## Deploy

Follow [Deployment Notes](DEPLOYMENT_NOTES.md) for the current file manifest.
Serve a reviewed static bundle rather than the complete repository, which
contains archived assets and unpublished material. Preview that bundle before
publishing. Deployment and pushing require an explicit request.
